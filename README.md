# 油品价格维护（调价账本）

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 引擎测试：`npm test`

把**油品、调价批次、生效版本、换班小票**接成一本账，解决两站控窗口同时改价 +
断网补送带来的覆盖与重复记账问题。数据保存在浏览器 localStorage（原子提交）。

## 账本规则

1. **占位**：`计划编号 + 油品` 决定生效位。同计划先到批次占位生效（产生新版本），
   后到内容转**待裁草稿**，不产生版本、不影响售价。
2. **合并**：断网包恢复时按字段（挂牌价/生效时刻/操作员）与占位批次比对，
   一致则幂等跳过；冲突**两值都保留**在草稿上，**经理确认前不计售价和差额**。
   仲裁可逐字段选“现值/来值”：采用则草稿占位生效（原占位者淘汰），拒绝则草稿淘汰。
3. **恢复**：批次是提交单位。写入顺序为“备份完整状态 → 提交标记 → 写新状态”，
   任意时刻保存失败都能从**完整批次**恢复；失败操作进待重放队列，恢复后重放。
   差额入账带幂等键（`班次|油品|版本|销量`），**重放不重复记差额**。
4. **重算**：价格或生效时刻改动后，**未确认小票失效重算**（冲回/重记成对出现，
   流水净额与入账合计恒等），**已确认小票保留原差额**。

## 结构

```
src/domain/types.ts    领域模型（批次/版本/小票/流水/冲突）
src/domain/ledger.ts   账本引擎（纯函数：占位、合并、仲裁、交班、重算）
src/domain/storage.ts  原子提交 + 完整批次备份 + 待重放队列
src/stores/ledger.ts   Pinia store：commit / 恢复重放
test/ledger.test.ts    四条规则的场景测试（node:test）
```

界面左侧为操作台（调价批次、断网补送、交班记账、保存失败演练），
中间为批次与经理仲裁，右侧为生效版本链与换班小票，底部为只追加的账本流水。
